Problem

Exercising Socially At Home

Socializing takes energy

After a long day of work or school, leaving the house to socialize requires time and energy most people don't have. There should be more ways to hang out without commuting anywhere.

Home exercise can be boring

Exercising in public is intimidating, but exercising at home alone is discouraging. There are few interactive, engaging options within the comfort of your own space.

Active games need extra hardware

Apps that encourage movement with friends usually require a separate console purchase.

Our solution

We wanted to create a fitness tennis game that makes it easy to get moving and play tennis wherever someone is. Using only a phone and a computer, players can turn their phone into a racket and their screen into a court, with minimal setup and no extra hardware. The game is designed to be easy to pick up, fun to play with friends, and accessible for getting some exercise at home or anywhere someone has space to play.

How It Works

Using Your Phone as A Racket

The main game runs on a desktop, which hosts the server and displays the 3D tennis court where the match takes place. Each player's phone acts as their racket, with accelerometer and gyroscope data read each frame and sent to the desktop server. The server processes the incoming motion data and game state, which is then displayed in the desktop game.

Different swing speeds determines ball speed as a gentle swing will produces a slower hit, while a fast swing sends the tennis ball flying. Racket orientation (phone orientation) determines the direction of the shot.

Technical: Networked Game

Multiplayer Architecture

Unity Netcode
Hybrid authority model

We used Unity Netcode for GameObjects with a hybrid authority model. Each phone is client-authoritative for its position, rotation. This allows the gyroscope, and accelerometer input, to directly reflect the player movement without noticeable lag required for fast-paced gameplay.


The desktop acts as the server authority for shared game state which manages the tennis ball’s position, physics, and the resulting reactions to each swing. Networked events such as serving, hitting, and scoring were also handled through the server to keep these changes synchronized across all connected devices.This keeps the game state consistent between players and prevents gameplay states from being modified by individual clients.

// Server receives swing input, applies physics, and syncs result
[ServerRpc]
void SwingServerRpc(Vector3 racketVelocity, Quaternion racketRotation)
{
    HitBall(racketVelocity, racketRotation);
    UpdateBallStateClientRpc(ball.position, ball.velocity);
}
Player lobby
Character selection sync

I created the player lobby system (IP connection) to manage character selection across devices. Character selection uses a NetworkListCharacterSelectState to maintain shared lobby state across clients. When a player selects a character, their client sends the selection through a ServerRpc, which checks the character ID and updates that player's networked state. Clients subscribe to OnListChanged to update their local UI whenever the shared state changes. Character availability is also checked against the networked player list so two players cannot lock in the same character. The “Start Match” button on the desktop screen only activates when both players have confirmed ready on their own devices.

Technical: Sensor Integration

Determining Swing Motion Thresholds

Translating sensor data into game actions
Gyroscope and accelerometer reading

Because the phone acts as the racket, we needed to determine how its physical orientation and movement should translate into the game. We mapped the phone's gyroscope orientation to the virtual racket, converting its coordinate system and applying an offset to align the physical and virtual racket positions. We then used accelerometer data to detect intentional swings, tuning motion thresholds through testing to distinguish a swing from smaller movements. Once a swing is detected, the accelerometer data is mapped to a force value and clamped to keep the resulting ball speed within a playable range. 

Quaternion newRot = Input.gyro.attitude;

// Convert gyroscope coordinates to Unity's coordinate system
float temp = newRot.y;
newRot.x *= -1;
newRot.y = -newRot.z;
newRot.z = -temp;

// Offset to align the physical and virtual racket
newRot *= Quaternion.Euler(-90, 180, 90);

if (Quaternion.Angle(
    racket.transform.rotation, newRot) > 3f)
{
    racket.transform.rotation = newRot;
}

if (!isSwingingBack &&
    Input.gyro.userAcceleration.magnitude > 2)
{
    // Map acceleration to swing force and clamp the range
    float force = Input.acceleration.magnitude - 2;
    force *= 4;
    force += 5;
    force = Mathf.Clamp(force, 5, 18);

    bh.StartSwing(force);
}
Testing and Debugging
Motion input calibration

We ended up using Unity Remote as well as creating builds on both Android and IOS for testing and debugging. Through this, we were able to find motion control issues with sensor reliability, particularly gyroscope drift.


Small changes in the phone’s reported orientation would accumulate over time, causing the virtual racket to gradually shift even when the phone was being held relatively still. Testing sensor values across Android and iOS devices showed differences in their reported orientation. To account for this, we track relative change per frame rather than absolute orientation, avoiding reliance on each phone’s individual baseline. To further filter out noise, we tested different thresholds and offsets for movement detection to reduce these fluctuations and maintain responsive controls for “real movement.”


These small orientation errors could make it difficult for new players to consistently control where the ball landed, so we implemented an adjustable aim assist that applies a velocity correction toward different areas of the opponent’s court based on their position. Since we parameterized the correction factor, players are able to adjust to what they prefer as it allows new players to have more assistance while more experienced to have more precise directional control. 

// Apply velocity correction toward a valid court target
private Vector3 AimAssist(float force)
{
    Vector3 aim = Vector3.Normalize(
        Vector3.MoveTowards(-ballPhysics.position, Vector3.zero, 1));

    aim = Vector3.ProjectOnPlane(aim, Vector3.up);

    aim *= ballPhysics.velocity.magnitude
        + Mathf.Max(speedCap - ballPhysics.velocity.magnitude, 0)
        * force / speedCap;

    aim.y = Mathf.Sqrt(
        (2 * targetHeight - ballPhysics.position.y)
        * Mathf.Abs(Physics.gravity.y));

    Vector3 correction = aim - ballPhysics.velocity;
    return correction;
}

Changes

From Prototype to Production

After finishing V1, I still felt there was more I wanted to explore with the project. V1 proved that we could connect two players, use their phones as tennis rackets, and have them play a real multiplayer tennis match. However, because the project was built as a prototype in a short amount of time, many aspects beyond the core gameplay were not fully considered.


This inspired me to continue the project with V2 and address the gaps that became apparent during development. The goal is to explore how the project could be restructured for a more production oriented environment while also refining the game's visual and player experience to a more polished level.


V2 is currently in development, so this page focuses more of the key architecture rewrites and visual decisions for the new iteration.

Visual Redesign

Visual Concept + UI

We wanted to introduce a new visual direction for the playable characters and overall game presentation. Our previous concept combined an arctic cyber aesthetic with animal characters, but we had a hard time making the two ideas feel connected. For V2, we wanted the characters and world to come from the same concept, creating a more consistent visual identity.

The new direction centers around a cosmic world where tennis has become a way to settle conflicts between factions. The playable characters are imagined as rabbit siblings competing for to win, with their story connected to a larger universe of warring factions. This gives the characters a place within the world while also making tennis part of the game's identity.

Visually, the game keeps the neon cyber aesthetic from the original concept while shifting it toward a more cohesive cosmic setting. These designs are still in development, but they establish the direction for the game's next iteration. Moving beyond the prototype also means reconsidering the UI, which was originally built to support development rather than a final player experience. I hope V2 explores a cleaner interface, clearer feedback, and a more consistent visual language across the lobby and gameplay.

Architecture Redesign

Architectural Improvements

The original prototype was built in a short amount of time, so some of the systems became closely tied together. For V2, I want to restructure the code by separating responsibilities such as phone input, racket control, networking, ball physics, match state, and scoring. The goal is to make these systems more modular so they can be changed or expanded without requiring changes across the rest of the codebase.
